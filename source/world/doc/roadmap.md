## 進め方の核：パターンを先に決めて、各々に当てはめる

個々のアイテム・アクションに個別の方針を立てようとすると終わらない。先に**型（パターン）**を数種類決め、あとは全要素をそのどれかに割り当てる作業にする。

決めるパターンは4種類。

```
カテゴリのパターン       … 25カテゴリを何種類の型に分けるか
アイテムの入手経路パターン … 全アイテムを「どうやって手に入るか」で分類 ← 中心
アクションのパターン     … 入手経路パターンと1対1で対応させる
スキルのパターン        … skill.csv は0行なので完全に新規
```

**アイテムの入手経路パターンがハブになる。** 「このアイテムは合成で作る／購入する／敵から落ちる／宝箱から出る」を決めれば、必要なアクションが自動的に決まり、アクションの `req`／`acq` の形も決まる。逆に言うと、ここを決めずにアクションを作ったから643本のボイラープレートが生まれた。

## 作業のリズム

全体像がまだ像を結んでいないので、**まとめて提案せず、細かく区切って確認しながら進める。**

- Claude は一度に1つの論点だけ出す。叩き台と選択肢を示し、決めるのはユーザー
- 決まったことはその場で plan.md / overview.md に書き足す（次の会話でも残る）
- 途中で前の決定を覆してよい。パターン段階で覆すぶんには手戻りが小さい（当てはめ後だと大きい）ので、**Step 1 では遠慮なく往復する**
- 「まだ判断できない」ものは保留リストに置いて先へ進む。他が埋まると自然に決まることが多い

## 作業場所と手段

**リポジトリは `idle` のまま。** ワールドデータはエンジンの型（`editor/type/worldType.ts`）に従属し、設計文書と world 系スキル（world-balance / world-playtest / world-color-scheme）も同じリポジトリにある。分離の適期は CSV→world.json の変換ができてワールドが自己完結してから。

**対話は「決める」ときだけ使う。** 900行を1行ずつ会話で確認するのは成立しないので、手段を役割で分ける。

| 作業 | 手段 |
|---|---|
| パターン・ルールを決める | 対話（Claude が論点を1つずつ出す） |
| ルールに基づく一括生成・一括変換 | Claude が CSV を直接編集 |
| 結果のレビュー | `git diff`（気に入らなければ revert） |
| 全体を眺める・目視で取捨選択する | **一覧ビュー**（[overview.html](../view/overview.html)。Step 2 で用意した。公開先は下記） |
| 決定・現在地の記録 | `world/` 配下の md |

かつての Excel 管理はほぼ機能していない（ファイルは残すが作業面としては使わない）。**そのぶん「眺める手段」が一覧ビューしかない**ので Step 2 で先に用意した（[overview.html](../view/overview.html)）。

### 一覧ビューの公開先

ブラウザで開くだけなら `world/view/overview.html` をローカルで開けば足りるが、共有用に
[yutori-gene/idle-world](https://github.com/yutori-gene/idle-world) の GitHub Pages へも出せる。

<https://yutori-gene.github.io/idle-world/>

**自動では公開されない。指示があったときだけ流す。** 手順は3つ。

1. `python3 world/tool/overview.py` で `world/view/overview.html` を作り直す
2. その中身を idle-world の `site/index.html` へコピーして `main` へ push
3. idle-world の Actions → **Publish overview to gh-pages** → Run workflow で発火

idle-world 側は `main` が「次に公開する内容」、`gh-pages` が「いま公開されている内容」。
`idle` は private だが **idle-world は public** なので、出すとワールドの中身は全部公開になる。
（idle-static への公開は別系統。git-pages スキルが正本）

重要なのは、**Claude が聞くのは個別の行ではなくルールだ**という点。「この素材残す？」を900回やるのではなく「rare5以上でどのレシピにも使われていない素材は削除」を1回承認して一括適用し、diff で結果を見る。

**1カテゴリ＝1コミット**にして、レビュー単位と巻き戻し単位を揃える。

## Step 1. パターンを決める（対話で、上から順に）

plan.md と terms.md に既に書かれている方針を「型のリスト」として書き下す作業。新しく決めるのではなく、**散らばっている方針を型に畳む**。

### 1-1. アイテムの入手経路パターン ← ここが本丸

全アイテムに付けるタグの候補を確定させる。叩き台:

| 入手経路 | どこで | 主な対象 | 対応アクション |
|---|---|---|---|
| 収集 | ダンジョン | 低〜中rareの素材 | 収集（persistent） |
| 討伐ドロップ | ダンジョン | 全rare帯・敵ごとに候補複数 | 戦闘（stamina） |
| 探索報酬 | ダンジョン | 高rare・進行素材 | 探索（single） |
| 宝箱 | ロフト | ランダム報酬 | 開錠（single） |
| 購入 | 売店 | 汎用素材・消耗品 | 購入（snap） |
| 合成で作る | 装備管理・作業部屋・寝室 | 装備・インフラ・美術品 | 合成 |
| 分解で戻る | 装備管理 | 素材 | 分解 |
| 栽培 | 温室 | 食材 | 栽培（persistent） |
| 調理・調合 | 台所・地下室 | 料理・ポーション | 料理／調合 |
| 読書で得る | 書斎 | 知識 | 読書 |
| ペット産出 | 庭 | 素材・食材 | ペット委任 |
| イベント報酬 | — | 特別品・進行素材 | （event.csv） |

決めること:
- この12個で足りるか／統合できるものはないか
- **1アイテムに何個までタグを付けるか**（複数経路を許すか、原則1本にするか）
- 各経路が全体の何割を担うか（＝アイテム分布の目標）

### 1-2. カテゴリのパターン

25カテゴリを型に分ける。叩き台: ダンジョン型10／生産型（温室・台所・地下室）／装備管理型5／購入型（売店）／開錠型（ロフト）／知識型（書斎）／委任型（庭）／保管型（倉庫）／拠点育成型（寝室・作業部屋）。

型ごとに「アイテムを持つか」「アクションは何種類置くか」「numeric か」「standalone か」を1回決める。

### 1-3. アクションのパターン

入手経路パターンと1対1で対応させ、型ごとに雛形を決める。

- progressType
- 命名パターン
- `req` の形（素材何種×何個 / 道具 / カテゴリLv）
- `acq` の形（単一確定 / rare別の抽選を何スロット）
- カテゴリ1つあたり何本置くか

**ここで装備の643本をどう畳むかが決まる。** 「装備1種につき作る＋分解するの2本」という現状の型をやめるか、残すなら旧系統207本を廃止して一本化するか、装備アイテム自体を204種から減らすか。

### 1-4. スキルのパターン

skill.csv は0行なので完全に新規。`chance` と5つの戦闘プロパティ＋`comment` しか列がないので、型は数種類で足りる（攻撃強化／防御強化／回復／会心／回避 など）。何種類作り、誰（アイテム側＝味方／アクション側＝敵）が持つかを決める。

**Step 1 の成果物**: 決めたパターンを plan.md に追記する。

| | |

**CSV を編集したら必ず作り直す。** Step 3 の各回は「CSV を直す → 再生成 → `git diff` で結果を見る」というリズムになる。

## Step 3. 当てはめる（カテゴリを1つずつ、対話で）

**順序**（上流＝下流を縛るものから）

```
倉庫・売店 → 温室 → 公園（ダンジョンの雛形）
→ 近接武器・防具（装備の雛形）
→ 森・街・海・北国・工場・火山・城・地獄・天空
→ 台所・地下室・書斎・ロフト・庭・寝室・作業部屋
→ 投擲武器・爆発武器・装飾
```

**各カテゴリで毎回同じ手順**

1. overview.md の該当セクションを一緒に見る
2. **アイテムを確定** — 残す／消す／改名／別カテゴリへ移す。足りないものを足す
3. **各アイテムに入手経路パターンを割り当てる**（1-1 のタグを付けるだけ）
4. **アクションを起こす** — 3 の割り当てから、1-3 の雛形どおりに必要な本数を出す
5. **数値は空欄のまま** — `level`／`seconds`／`experience`／`chance`／`count` は Step 4 で plan.md の公式から一括計算する
6. CSV に反映し、overview.md と session.md を更新

公園・近接武器・防具は**雛形回**。ここで確定した構成を plan.md に書き残し、以降のカテゴリはそれをなぞる。
