## エンジン用語（型定義ベース）

### データ構造

| 用語 | 型/フィールド | 説明 |
|------|-------------|------|
| ワールド | `World` | ゲーム全体の定義データ |
| カテゴリ | `Category` | 活動場所または装備管理区画。レベルあり |
| アクション | `Action` | カテゴリ内で実行できる行動 |
| アイテム | `Item` | 入手・消費・装備できるオブジェクト |
| グループ | `groups` | アイテム/カテゴリの分類ラベル |
| スキル | `Skill` | 戦闘中に確率で発動する追加効果。ワールド直下に実体を置き、アクション（相手側・複数）とアイテム（味方側・単数）からIDで参照する。**`stamina` アクション専用**で、持てるのは戦闘5値（attack / defence / accuracy / evasion / restore）だけ。**100種すべて敵味方共通**（plan.md「スキルの雛形」） |
| タスク | `events.tasks` | 条件を満たすと達成になるミッション（`timing`は`tasked`固定） |
| 変化イベント | `events.changed` | 数量が一度に条件量以上増えた時に発動する内部処理用イベント（`timing`は`changed`固定）。UIには一切出ない |
| イベント | `events.unique` | 決まったタイミングで発火する出来事。タイミングごとに1つずつ固定 |
| プリセット | `presets` | ゲーム内で参照される汎用情報 |

### アクション関連フィールド
`progressType`（進行方式）/ `experience`（経験値）/ `seconds`（秒数）/ `chance`（成功率0〜1）/ `maximum`（最大回数）/ `acquisitions`（取得物）/ `requirements`（必要条件）/ `attribute`（分類タグ）

### 進行タイプ（`ActionProgressTypes`）

| 値 | 日本語 | 説明 |
|----|--------|------|
| `persistent` | 継続 | 時間で進行。オフラインも進む |
| `single` | 単発 | 1回ずつ手動実行 |
| `snap` | 瞬間 | 即時完了 |
| `stamina` | スタミナ | ターン制戦闘。初回HP回復→攻防判定。敗北で失敗、consumableは完了時消費 |

### アイテム関連フィールド
`buyingValue`（購入価格、0以下=購入不可）/ `sellingValue`（売却価格、0=売却不可）/ `coinId`（売買に使う通貨ID、空欄はメイン通貨）/ `equipmentType`（装備挙動）/ `properties`（装備時のステータス加算・カテゴリ別に複数持てる）/ `skill`（味方側スキルIDの参照）

### 装備タイプ（`EquipmentTypes`）

| 値 | 日本語 | 説明 |
|----|--------|------|
| `necessary` | 装備必須 | 装備して効果発揮 |
| `unnecessary` | 装備不要 | 所持するだけで効果発揮 |
| `impossible` | 装備不可 | 消耗品・素材など |
| `consumable` | 消費装備 | 使うたびに消費（投擲など） |

### プロパティ（`PropertyTypes`）
`attack`（攻撃）/ `defence`（防御）/ `accuracy`（命中率）/ `evasion`（回避率）/ `restore`（HP回復）/ `speed`（アクション速度倍率）/ `chance`（成功率補正）/ `experience`（経験値補正）

### イベントタイミング（`EventTimingTypes`）

`tasked`は`events.tasks`、`changed`は`events.changed`（どちらも配列・自由に追加可能）、それ以外は`events.unique`（タイミングごとに1つずつ固定・追加削除不可）に置く。

| 値 | 格納先 | 日本語 | 説明 |
|----|--------|--------|------|
| `tasked` | `events.tasks` | 条件一致 | 条件を満たした瞬間。ミッション・タスクの一覧に表示される |
| `changed` | `events.changed` | 変化時 | 数量が変化するあらゆるタイミングでチェックし、**その1回分の増加量**が条件を満たせば発動。何度でも繰り返す。UIには一切表示されない |
| `comebacked` | `events.unique` | 復帰時 | オフラインから進行付きで再開した時 |
| `gameovered` | `events.unique` | ゲームオーバー時 | 戦闘でスタミナがなくなった時 |
| `welcomed` | `events.unique` | 初回開始 | 初めてゲームを開いた時 |
| `completed` | `events.unique` | 完了時 | 全カテゴリが最大レベルに達した時 |
| `obtained` | `events.unique` | 単発完了時 | `single`アクション（宝箱など）を完了・確認した時 |

`tasked`とそれ以外はプレイヤーでの振る舞いが異なる。

| 振る舞い | `tasked`（タスク） | `tasked`以外（イベント） |
|----------|--------------------|--------------------------|
| 達成・発動時のトースト | 初回の達成時のみ出す | 出さない |
| 達成・発動時のイベントカラム | 開かない | 開く |
| 報酬の獲得 | `receive`バーを押した時 | 発動と同時に自動 |
| 報酬獲得時の紙吹雪 | `receive`バーを押した時のみ | 出さない |
| バーのリボン | 達成かつ報酬未受け取りの時のみ | 常になし |

タスクの状態は`user.Event`の3フラグで表す。

| フラグ | 意味 | 挙動 |
|--------|------|------|
| `released` | 一度でも達成したか（履歴） | 単調に立て、条件を失っても戻さない |
| `matched` | 今この瞬間に条件を満たしているか | 条件に追従して戻る。初回達成の検出にのみ使う |
| `claimed` | 報酬を受け取ったか（終端） | 立つと以後`check()`の対象から外れる |

**一度達成したタスクは達成のまま固定する。** 表示（`getArchived`）・解放判定（`economy.check.isReleased`）・報酬の受け取り権利（`checkUnclaimed`）はすべて`released`を見るため、達成後に条件を満たさなくなっても未達成へは戻らず、アイコンに斜線も付かない。報酬もいつでも受け取れる。`claimed`が立つと`check()`が回らず`matched`が凍結するため、受け取り時に`matched`を`true`で確定させる。

報酬の受け取りはアクションの実行や購入と同じく`canAcquireItems()`で容量（アイテムの種類数の上限）を確認し、超える場合は`capacity-full`のトーストを出して受け取らせない。リボンは残るので整理してから受け取り直せる。

## ゲームコンテンツ用語

**全24カテゴリ** = ダンジョン系10 + 拠点系14（生産3・知識1・雑多3・装備管理5・拠点育成2）
※ 売店は廃止。購入はアイテムの `buyingValue` で表現する（plan.md「購入型の雛形」）
※ 分類別の一覧・ダンジョン順・難易度は `plan.md` の「ダンジョンノード骨格」を参照

### アイテムグループ

| グループ名 | 装備タイプ | 買 | 売 | 説明 |
|-----------|----------|----|----|------|
| 加工品 | `impossible` | × | ○ | 倉庫の合成2本・分解4本は廃止。`ATM`・`体重計`・`アークリアクター` は**売るためのお宝**（ダンジョン・宝箱の報酬）、`双眼鏡` は作業部屋、`ワクチン` は地下室へ本籍移設。`バケツ` は削除 |
| 素材 | `impossible` | ○ | ○ | 汎用素材。**初期から購入可** |
| ゴミ | `impossible` | × | ○ | 売値はperiod連動（1〜10コイン） |
| 食材 | `impossible` | △ | ○ | 一部そのまま食べられる |
| 料理 | `impossible` | × | ○ | 食べて回復など |
| ポーション | `impossible` | × | ○ | 消費して戦闘5プロパティを一時強化。**本籍はすべて地下室**（ダンジョンに置かれていた4種も移す） |
| 本 | `impossible` | △ | ○ | 書斎で読んで知識取得 |
| 知識 | `unnecessary` | × | × | 所持でプロパティ加算または条件達成 |
| 能力 | `unnecessary` | × | × | 知識と同じ扱い。読書で入手する。**スキルの器10種**で、`unnecessary` なので所持しているだけで常時抽選の候補に並ぶ（外せない）。`maximum` は全種 `1` に揃える |
| 宝箱 | `impossible` | × | × | ロフトで開錠 |
| 道具 | `necessary` | △ | ○ | 特定アクションに装備必要。**消えない**（`req` は `equipment=true, chance=0`）。本籍は**使用先カテゴリ**（森・海・ロフト・温室・作業部屋など）。⚠️ 69種中45種が `acq`・`req` ともゼロの死にアイテムで、仕分けは Step 3 |

| ペット | `unnecessary` | × | × | ダンジョンの討伐で低確率入手。庭で委任（アクションのグループは `遊ぶ`）。`maximum=1`（所持数比例の補正が青天井になるため）。18種（2026-10-30） |
| 近接武器 | `necessary` | △ | ○ | 消費しない戦闘武器。継戦型（restore＋）。**例外的に consumable の強武器あり** |
| 投擲武器（弾） | `consumable` | △ | ○ | 1アクションごとに1個消費。手数型（accuracy＋/speed＋） |
| 投擲武器（射出装置） | `necessary` | △ | ○ | 弾と**同時装備**する消費しない枠 |
| 爆発武器 | `consumable` | △ | ○ | 1アクションごとに1個消費。一撃型（attack最大・accuracy−/speed−）。**例外的に necessary の控えめ品あり** |
| 頭部/胴体/腕部/脚部防具 | `necessary` | △ | ○ | **装備条件なし**（Step 3-5 で全削除。防具カテゴリは `numeric=false` でレベルが上がらないため条件が永久に満たせなかった） |
| アクセサリー | `necessary` | △ | ○ | 全プロパティ+補正。**装備条件なし**（防具と同じ理由。装飾の回で適用） |
| ブローチ | `necessary` | △ | ○ | プラス/マイナス両方の補正。**装備条件なし** |
| 指輪 | `necessary` | △ | ○ | 特定カテゴリのみに補正。**装備条件なし** |
| 美術品 | `necessary` | × | × | 寝室で飾る。**置き場所3グループに分け、グループごとに1つだけ効く**（同時3つ）。売却不可。経験値UP |
| インフラ | `unnecessary` | × | × | 作業部屋で合成。所持数比例でアクション速度UP。**売却不可**（部品100個を投じて作るため） |

**売却不可は99種**（容器9・ペット19・知識15・能力10・美術品14・宝箱18・インフラ14）。**恒常プロパティを供給するアイテムはすべて売却不可**で揃う。容器の売却不可は**エンジン上の必須制約**で、売って買い直すと `changed` が再発火して capacity が青天井になる（fix.md B-9）。

※ 買の△ = 解放条件あり（初期は購入不可）。解放は `Item.requirements`（カテゴリLv／アイテム所持）で組む

**`req` に置くアイテムの役割は「材料」と「道具」の2つだけ。** 材料は消える（`chance>0`）、道具は消えない（`chance=0`）。カテゴリごとにどちらを使うかが変わり、**本は道具ではなく材料**（読書1回で消費される）。詳細は plan.md「`req` に置くアイテムの役割は2つだけ」節。

## 決定事項

- **ロフトの宝箱**: 種類ごとに開錠アクション1本ずつ。requirements=宝箱1個所持、acquisitionsで中身。period応じて進行タイプ・秒数調整
- **購入方針**: 購入は**エンジンのネイティブ機能**（アイテムのページ → `buyingValue`）で行う。売店カテゴリとその36アクションは廃止した（plan.md「購入型の雛形」）。基本は購入不可（`buyingValue=0`）で、例外は「素材グループ（初期アンロック）」「購入前提の消耗品」「アクション報酬に組めなかった補完品」の3つだけ。`buyingValue = sellingValue × 2` なので**購入可の必要条件は `sellingValue > 0`**。解放条件は `Item.requirements` で表現する
- **購入アクションの唯一の例外は器具6種**: `フライパン`・`鍋`・`ボウル`（台所）と `すり鉢`・`蒸留器`・`るつぼ`（地下室）は `Action.level` で解放段階を付けたいので、`single`・`req = コイン xN` のアクション6本として作る。`group.csv` の `購入,action` はこの6本のために残す（plan.md「旧系統の掃除」）
- **スキルは100種・敵味方共通**: 味方の器は**能力10種＋武器42・防具20・装飾18・ポーション10**の計100アイテム（1アイテム1スキル）。知識・ペット・容器・インフラ・美術品には持たせない。同時に抽選へ並ぶ候補は**22**（能力10＋装備12枠）で、`chance` は 0.03〜0.12・効果量は ±3〜15。敵は討伐1本あたり 0〜3本（ボスは4本以上）。**敵側だけに掛かる確率の倍率はエンジンに無い**ので改修要望として起票済み（fix.md B-12）
- **コインの入り口は売却**: `acq` にコインを持つアクションは20本・1回1〜8枚しかない。主な資金源は売却で、基礎収入は `group=ごみ` 59種。売却はインベントリ容量（アイテムの種類数）の管理も兼ねる
- **価格は装備204種以外ほぼ未設定**: 公式 `round(3^rare × period)` が効いているのは装備204種だけ。装備以外は手入力98種＋未設定603種で、Step 4 で引き直す。`buyingValue > sellingValue` は不変条件（逆転するとコインが無限に増える）
